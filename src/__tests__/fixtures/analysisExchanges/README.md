# Real analysis exchanges

Twelve stored exchanges of the technical analysis path: the dynamic prompt the model was
sent and the text it answered. They pin the deterministic checks (`checkPriceProvenance`,
`checkPlanInvariants`) and the normalizer chain against real model output. They are prompt
version `p32` exchanges, so they say nothing about the quality of current model output.

## Source

All twelve come from one published backtest run, `2026-11-daily-ai` (release tag
`backtest-2026-11-daily-ai` of the public siglens repository): daily bars, model
`deepseek-v4.1-flash`, tier `member`, reasoning off, prompt version `p32`. The same run's
prompts and post-processed responses are already public as that release's
`prompts-and-responses` asset; the files below are the stored HTTP exchanges behind those
entries.

Each file is `{ id, source, ticker, date, promptVersion, lastClose, atr, dynamic, rawText }`,
gzipped JSON:

- `dynamic` is the request `input` of the stored DeepSeek exchange (the system prompt, request
  options, response metadata and headers are not copied; there was no auth header to begin with);
- `rawText` is the concatenation of that response's `response.output_text.delta` events;
- `lastClose` and `atr` are the unrounded `close` and `indicators.atr` of the run's dataset day
  record for `date`.

No secret, API key, user data or host name is in any file: the prompts are built from public
market data, and the run had no user input (prior analyses in the prompt are the run's own).

The files are produced by `scripts/fixtures/buildAnalysisExchangeFixtures.ts --v8-data <dir>`
from a local copy of the run's data (`ai/raw/<TICKER>/<hash>.json.gz`, `ai/<TICKER>.json`,
`dataset/<TICKER>.json.gz`). It scans every stored exchange in sorted (ticker, key) order and
takes, per class and in the order below, the first matches not already taken, preferring a
ticker no earlier pick used. Where an exchange file holds a retry, the last HTTP 200 exchange is
used.

`expected.json` is generated by the same script (once) and pins each file's class, its
`checkPriceProvenance` report and its false-grounding rate; `src/__tests__/scripts/fixtures/analysisExchangeFixtures.test.ts`
reads it.

## What these files do not exercise

- **Pattern geometry.** The fixtures are evaluated with no overlay candidates, so
  `alignPatternGeometry` strips the geometry of every detected card and the
  `patternGeometry` provenance field sees nothing. Rebuilding the candidates from the stored
  bars would use today's prompt builder, whose candidate ids need not match the p32 ids the
  model cited, so it is not attempted. That field is covered by synthetic tests only
  (`priceProvenance.test.ts`).
- **KRW and other whole-unit listings.** The run is US only. KRW is covered by a prompt built
  by `buildAnalysisPrompt` from constructed bars (`priceProvenance.test.ts`), not by a stored
  exchange.

## Known measurement limits

Both numbers are produced by the builder script (`--report`, and the pinned
`falseGroundingRate` of each entry in `expected.json`) and are properties of the check, not of
the model.

**False grounding.** A price counts as printed when the computed sections of the prompt print
a number at the same precision within 0.6 units of the last digit. A prompt prints well over
a hundred prices near the close (bars, levels, pivots, Fibonacci tables), so a price picked
at random can be "grounded" by chance. `falseGroundingRate` is the share of prices on the
price grid within ±10% of the last close that count as grounded:

- per fixture: 1.05% (TSLA) to 5.59% (NVDA), mean 3.0% over these twelve;
- over all 3,493 evaluable stored prompts: mean 2.47%, median 2.05%, min 0.35%, max 7.17%;
- before this version excluded guidance sections, dates, times, percentages and negatives, the
  same twelve prompts measured 1.33% to 6.14%, so the exclusions remove about a tenth of the
  chance matches and the rest comes from real printed prices.

An ungrounded-price rate near these figures cannot be told from noise on a single plan; it is
meaningful as a rate over many plans, next to the control. For whole-unit prices (KRW) the
rate depends on the same density at 0 decimals and has to be measured per prompt.

**Strict ungrounded rate** over all 3,493 evaluable stored plans (prompt version p32, no
round-number exemption, plan prices read before any rounding):

- plans with at least one ungrounded plan price: 326 (9.3%);
- ungrounded plan values: 400 of 21,273 (1.9%);
- ungrounded model key prices (reported separately, never mixed into the plan rate): 22 of
  7,911 (0.28%).
